# v0.4 setup and acceptance

Development uses `codex/v0.4` in [Okasani/PaixAI](https://github.com/Okasani/PaixAI). An initial import commit preserves
the local v0.3 baseline; v0.4 changes follow separately. No release tag is created until live acceptance passes.

## Configuration migration

Persona YAML is now JSON, including reset defaults. Back up any custom persona directory and translate its four
YAML objects to matching JSON files. Validate before starting. The Jinja prompt template remains developer-owned;
ordinary customization uses JSON. Conversation and approved-memory SQLite data is not deleted or migrated.

Precedence is explicit arguments â†’ environment â†’ `.env` â†’ JSON â†’ defaults. Profiles validate together at startup.
Each turn loads a complete validated persona, so an invalid section cannot produce a partial persona. API section
edits validate before replacement. Restart for runtime, voice or avatar profile edits; rebuild after knowledge edits.
Schemas are in `config/schemas/`, generated by `python -m app.diagnostics.cli schemas` from `backend`.

## Knowledge commands

Documents have `schema_version`, unique `id`, `title`, `content`, and `source` in `config/knowledge/*.json`.

```powershell
./scripts/paix.ps1 import ./notes.md --id project-notes --title 'Project notes'
./scripts/paix.ps1 validate
./scripts/paix.ps1 rebuild
./scripts/paix.ps1 query 'deployment notes'
./scripts/paix.ps1 inspect
./scripts/paix.ps1 export ./knowledge-export.json
./scripts/paix.ps1 backup ./owner-backup.json
```

Imports accept UTF-8 text/Markdown and never overwrite an identity. Rebuild validates every source before replacing
the derived index atomically. Unchanged sources produce identical output. Stale sources require a rebuild; a missing
index permits chat without knowledge. Hits include source filename/label, document/chunk ID, content hash and exact
character offsets. Prompt context escapes JSON delimiters and treats retrieved text as untrusted data. Source-citing
instructions are included, but actual model citation fidelity requires answer QA.

Embeddings are sparse lexical TF-IDF on CPU, with no neural-model download or GPU cost. Paraphrases with no matching
terms may miss. PDF/Office imports and neural semantic retrieval are not implemented. `export` and `backup` contain
owner data; diagnostic trace exports are separate and content-free.

## Local voice setup

Style-Bert-VITS2 is the integration candidate for its selectable styles and local voice models. This is an engineering
selection, not a completed voice-quality benchmark. The installer pins upstream commit
`66de777e06392c0f313600be03c43ef96658b244`. Upstream code is AGPL-3.0; voice models have separate terms.
See [upstream](https://github.com/litagin02/Style-Bert-VITS2) and its
[license](https://github.com/litagin02/Style-Bert-VITS2/blob/66de777e06392c0f313600be03c43ef96658b244/LICENSE).

[Kokoro](https://github.com/hexgrad/kokoro), with its compact 82M model and Apache-licensed code/weights, and
[Piper](https://github.com/OHF-Voice/piper1-gpl), another local speech engine, were considered as alternatives.
Neither is integrated. Anime-style suitability is voice-dependent; no candidate has been benchmarked here.

1. Run `scripts/setup-local-tts.ps1`. It installs libraries in `.venv-tts`, separate from the minimal backend.
   This installer has not been exercised with licensed voice assets in the implementation checkout.
2. Supply approved `.safetensors`, model configuration and style vectors. Provision the upstream language/BERT
   resources using upstream setup instructions. Set `bert_paths` in the asset file to local model/tokenizer directories
   (for example `EN` → the local `microsoft/deberta-v3-large` snapshot).
   The bridge sets `HF_HUB_OFFLINE` and `TRANSFORMERS_OFFLINE`; it never downloads voice resources during inference.
3. Copy `config/voice-assets.example.json` to ignored `config/voice-assets.json`. Set paths, license reference,
   and `approved: true` for an approved model. Paths resolve relative to that file. The example is disabled.
   Start on CPU to preserve LLM VRAM; benchmark before selecting CUDA.
4. Set matching license reference and `assets_approved: true` in `config/voice.json`. Choose a supported speaker,
   language and style. The bridge hosts one model, ID `0`.
5. Run `scripts/run-local-tts.ps1`. It binds only to `127.0.0.1:5000` and accepts JSON bodies rather than text URLs.
   It does not use the upstream broad API server or its request-text logging.
6. Run `scripts/paix.ps1 doctor`, then the normal voice runtime. Missing TTS remains explicit; no cloud fallback occurs.

The engine synthesizes a whole phrase before PCM is yielded: phrase streaming, not within-phrase neural streaming.
The worker stays loaded between phrases. Cancellation terminates it and discards late audio; the next request reloads
the voice. Worker stdout/stderr are suppressed and only static errors cross the bridge. Real latency, restart cost,
pronunciation, quality and GPU coexistence remain unmeasured.

## Diagnostics

`doctor` checks configuration, local provider health, STT/audio dependencies, RAG, stage port and optional GPU tools.
It does not infer rendering from a listening socket or download STT models to test installation. Results explicitly
distinguish skipped/unavailable checks. `smoke` exercises mock generation â†’ phrase â†’ PCM â†’ avatar mapping with an
isolated temporary database; microphone and real rendering are skipped.

Opt-in traces rotate around 5 MiB. Export revalidates records and preserves only safe event metadata, states and
latency metrics. Session/turn IDs are hashed and arbitrary payload data is excluded. The API bug report also excludes
submitted content and local paths.

- Compile/import/build Unity with licensed SDK/model assets. Compare framing, every state/motion/expression,
  blink/breath/gaze, mouth closure, reconnect and interruption behavior against v0.3.
- Set `RUN_LIVE_API_TESTS=1` for live tests. Perform microphone â†’ local STT â†’ local LLM â†’ local TTS â†’ speaker turns;
  verify pronunciation, audible lip-sync, cancellation and absence of surviving inference workers/late audio.
- Measure cold/warm first-audio latency and peak concurrent VRAM on the 8 GB target. No unverified numerical
  latency or quality claim is made by this implementation.
- Edit persona/knowledge, validate/rebuild, and verify sourced answers. Review actual model behavior when documents
  contain instruction-like text, in addition to the automated prompt-boundary checks.
- Export a failed-turn trace and confirm useful subsystem diagnosis without private content.
